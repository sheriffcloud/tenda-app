Why a feed, not a stat row

Stats can be made up. A feed feels caught — every row is an event with an actor, a place, and a hash. Same persuasion goal as the Hero stat row but with motion + specificity. Where Hero says "fast," this section shows fast.

Six event types, six pill colors

LOCKED blue · PROOF orange · APPROVED green · SETTLED bone-on-black · DISPUTE red · CANCELLED grey. Mirrors the §4 stage palette plus two failure states. Reader builds the lexicon by row 3.

Plausible data only

Every row is checkable: real Tenda category (DEL/PHOTO/SVC/ERR/DIG/EXCHG), real fiat corridor (NGN/GHS/KES/ZAR/PHP), real fee math (2.5%). Includes one DISPUTE and one CANCELLED — failure modes are part of the proof.

Header chrome = explorer

Terminal dots, tenda://events.tail path, filter chips, sparkline footer, "View on Solscan ↗". Visual loan from block-explorer UIs (Solscan, Etherscan) — borrows their authority for free.

Motion

Top row slides down from -100%, opacity 0→1, green edge fades over 1.6s, bottom row drops off — every ~3s. prefers-reduced-motion swaps to a static "last 10 events." Sparkline cycles bars left→right (200ms step). LIVE dot pulses (1.6s).
