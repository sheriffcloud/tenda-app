FALLBACK · WHEN THINGS GO WRONG

If proof is missing or contested, escrow resolves — it doesn't disappear.

Funds are never stuck on Tenda. The program supports four exits — three automatic, one human-reviewed. Whichever path triggers, both parties see the same on-chain receipt.

A Mutual cancel. Either side cancels before work starts → SOL returns to poster. ~2s
B Auto-approve. Poster doesn't review within 48h of proof → release fires automatically. 48h
C Auto-refund. Worker doesn't submit proof before deadline → SOL returns to poster. deadline
D Dispute. Either side opens a dispute → Tenda reviewers split the locked amount based on submitted evidence. ≤ 24h

From the on-chain program

// every release is one of four paths
match escrow.state {
  Approved  → split(payout, fee),
  AutoApproved → split(payout, fee),
  Refunded  → return(poster),
  Disputed  → arbitrate(),
}

Two layers, one event

Verb + plain body sit above the rule; the on-chain receipt sits below. The reader can skim the human story or read the machine receipts — they describe the same event in different vocabulary.

Color = role, not stage

Blue stages (1, 3) = poster/buyer actions. Orange stage (2) = worker/seller action. Green stage (4) = program-level atomic settlement. Reads as a conversation, not a progress bar.

Resolve / dispute is non-optional

Brief asked for "what if?" coverage. Four explicit routes (A/B/C/D) with timeouts. Right column shows the actual match arms from the program — receipts > marketing.

Footnoted authority

Top-right meta block: PROGRAM id, CHAIN, AUDIT. Lets the trust claim ground itself without a hero stat row repeating §1.

Motion

Track-rule draws left-to-right (scaleX 0→1, 800ms) on enter. Stage cards fade up with 120ms stagger. PROOF SUBMITTED dot pulses (already coded). Monospace amounts roll up on first view (+200ms each).
